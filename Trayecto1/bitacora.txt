2. Rol de HTML, CSS y JavaScript

- HTML: define la estructura, el contenido y el significado de la interfaz.
  Ejemplo concreto de las etiquetas y pestañas;
  en reservas.html, `form`, `fieldset`, `legend`, `label` e
  `input` organizan la reserva y permiten validar campos como correo, fecha y
  cantidad.
- CSS controlará la presentación visual, el espaciado, la distribución
  responsive y el contraste. Ejemplo concreto para este sitio:
  `body { color: #1F2937; background: #FFF8E7; }` y un estilo de enlace o
  botón con color de foco visible.

- JavaScript añadirá comportamiento que HTML no cubre por sí solo. Ejemplo
  concreto: escuchar el evento `submit`, mostrar un resumen accesible de la
  reserva y actualizar dinámicamente el costo según el tipo de bicicleta, el
  plan y la cantidad. No se agregó JavaScript todavia por que esta en construcción desde cero de estructura,
  pero el formulario actual funciona con validación HTML nativa.

7. Justificación de controles

- Nombre completo: `text`, porque recibe texto; es obligatorio y tiene mínimo
  3 caracteres.
- Documento: `text` con `pattern`, porque se valida como una cadena de 6 a 10
  dígitos.
- Correo: `email`, porque el navegador valida su formato.
- Celular: `tel`, porque representa un número telefónico; exige 10 dígitos y
  comienza por 3.
- Fecha: `date`, con mínimo 2026-11-01 y máximo 2026-12-31.
- Tipo, plan y recorrido: `select`, porque las alternativas son limitadas y
  cada selección es obligatoria.
- Cantidad: `number`, con valores entre 1 y 6.
- Comentarios: `textarea`, porque permite texto libre y es opcional.
- Políticas: `checkbox` obligatorio, porque registra una aceptación explícita.

- Todos los documentos tienen `lang="es"`, `charset` y `viewport`.
- Los encabezados siguen una jerarquía de página, secciones y artículos.
- Los campos del formulario tienen `label` asociado mediante `for` e `id`.

  semántica ambigua.

PROCEDIMIENTO REALIZADO:

Se inspeccionaron los elementos de la página mediante las herramientas de desarrollador del navegador (DevTools). Se revisaron las propiedades CSS y los valores mostrados para cada elemento.

RESULTADO:

Se identificó color como una propiedad que se hereda y display como una propiedad que no se hereda. Los valores registrados corresponden a los observados durante la inspección.

Nota: Para confirmar directamente la herencia de color, se debe verificar en la pestaña Styles que el valor del elemento hijo provenga del elemento padre.



Análisis de especificidad:

a: especificidad (0, 0, 1).

.active: especificidad (0, 1, 0).

#menu: especificidad (1, 0, 0).

#menu a: especificidad (1, 0, 1).

#menu a.active: especificidad (1, 1, 1).

Resultado de la inspección:

En DevTools observé que la regla #menu a.active aparece sin tachaduras y establece el fondo verde claro mediante var(--color-verde-claro) y el color del texto mediante var(--color-azul-oscuro). También comprobé que existe otra regla general, #menu a, que define las propiedades de los enlaces del menú.

Causa identificada:

En la inspección realizada no se encontró evidencia de que la clase active estuviera fallando, ya que el navegador reconoce la regla CSS correspondiente y muestra sus propiedades como activas. Por lo tanto, no fue necesario modificar esta clase.

Conclusión:

Aprendí a utilizar DevTools para inspeccionar elementos HTML, verificar las clases CSS y comparar la especificidad de los selectores. También comprendí que una regla con mayor especificidad puede prevalecer sobre otra cuando ambas establecen la misma propiedad y no intervienen otros factores de la cascada CSS.

CIERRE DE BITÁCORA SEMANAL

Durante esta semana trabajé en el desarrollo del proyecto Rueda Libre Medellín, aplicando los conocimientos de HTML y CSS aprendidos en los diferentes MiniRetos.

¿QUÉ CONSTRUÍ EN LOS MINIRETOS?

En los primeros MiniRetos trabajé en la estructura de las páginas HTML, organizando los encabezados, títulos, párrafos, imágenes, enlaces y diferentes secciones del contenido.

Después, trabajé en los estilos CSS para mejorar la presentación visual de las páginas. Aprendí a utilizar variables para definir colores, fuentes y espacios, y a organizar los elementos para mantener una apariencia coherente.

En los ejercicios de formularios trabajé con campos de entrada, etiquetas, botones y atributos de validación HTML. También realicé pruebas con datos incorrectos para comprobar el comportamiento de las validaciones.

Además, mejoré la presentación de las imágenes y las tarjetas de servicios, agregué una etiqueta para destacar contenido nuevo y configuré un enlace fijo de WhatsApp que permanece visible al desplazarse por la página.

¿QUÉ APRENDÍ?

Aprendí que HTML permite estructurar el contenido de una página, mientras que CSS permite definir su apariencia. Comprendí que los selectores sirven para aplicar estilos a elementos específicos y que las variables CSS facilitan el mantenimiento de los colores, las fuentes y los espacios.

También aprendí a identificar errores en las rutas de los archivos, a relacionar las páginas HTML con una hoja de estilos compartida y a interpretar errores 404, como el que apareció al buscar el archivo favicon.ico.

Durante los ejercicios comprendí que algunos errores se producen por pequeños detalles de sintaxis, nombres de clases incorrectos o rutas mal configuradas. Por eso, es importante revisar el código y probar los cambios en el navegador.

CLASES DE BOOTSTRAP CONSULTADAS

1. navbar-expand-lg
Permite que el menú de navegación se muestre expandido horizontalmente en pantallas grandes y como menú desplegable en pantallas pequeñas.

2. d-flex
Activa el sistema Flexbox para organizar los elementos de un contenedor.

3. flex-column
Organiza los elementos de forma vertical, uno debajo del otro.

4. flex-md-row
Organiza los elementos en fila horizontal desde el tamaño mediano de pantalla (768px).

5. justify-content-between
Distribuye los elementos dejando espacio entre ellos dentro del contenedor.

Conflicto: Bootstrap establecía colores predeterminados para los enlaces del menú, mientras que mi diseño necesitaba mantener el color blanco sobre el fondo verde.
Solución: Personalicé los estados normal, hover y active utilizando los colores definidos en mis variables CSS.

3. Distribución del encabezado:
Revisión: Inspeccioné la clase .barra-superior con DevTools.
Resultado: La distribución Flexbox de mi CSS funciona correctamente y no encontré declaraciones incompatibles.
Solución: Conservé la configuración existente.

MEDICIÓN Y EXPERIENCIA:

En la prueba con Bootstrap pude organizar las tarjetas y el menú rápidamente,
usando clases como container, row, col e img-fluid. Esto redujo el tiempo de
trabajo, como ya había registrado en la bitácora.

En la prueba con Tailwind utilicé clases directamente en el HTML, por ejemplo
flex, grid, p-4, rounded-xl y text-center. El archivo input.css tiene 33 líneas
y el proyecto genera el archivo output.css automáticamente.

RECOMENDACIÓN PARA RUEDA LIBRE:

Recomiendo continuar con Tailwind para Rueda Libre. Aunque al comienzo se deben
aprender más clases, permite mantener los colores, botones y tarjetas con el
estilo propio del proyecto. Además, facilita adaptar la página a celulares,
tabletas y computadores.

Bootstrap sigue siendo una buena opción para crear una página rápidamente,
pero Tailwind se adapta mejor a la imagen personalizada de Rueda Libre.
